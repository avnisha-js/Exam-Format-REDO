PROJECT: EXAM FORMAT REDO
PHASE: CORE PHASE 1 ONLY
STATUS: BRAND-NEW PROJECT — DO NOT USE OLD EXAM FORMAT CODE

========================================================
A. PURPOSE
========================================================

Build the smallest possible proof-of-concept that can understand the
structure of ONE real, messy English Grade 10 teacher exam and normalize
its question numbering.

This is NOT yet an exam formatter.

CORE Phase 1 does ONLY:

Teacher DOCX
    ↓
Extract document blocks
    ↓
Whole-document hierarchy discovery
    ↓
Canonical exam structure
    ↓
Deterministic numbering
    ↓
Simple diagnostic output
    ↓
Integrity validation

STOP THERE.

Do not build anything else.

========================================================
B. FIXED INPUT FILES
========================================================

There are exactly TWO input files for Phase 1.

1. Teacher Exam

Teacher Exam English 10 Actual.docx

This is the REAL input that must be understood.

It contains intentionally inconsistent teacher-created structure.

DO NOT clean this file.
DO NOT modify it.
DO NOT create a simplified substitute.

2. Reference Exam

Reference Exam English 10 WORD.docx

This is a REFERENCE ONLY.

It demonstrates the intended structural conventions.

It must NEVER be used as a source for academic content in the Teacher Exam.

The Teacher Exam's wording, passages, questions, choices, marks, order,
and images are authoritative.

========================================================
C. IMPORTANT DESIGN PRINCIPLE
========================================================

DO NOT build a collection of regex patches for individual paragraphs.

DO NOT attempt to infer hierarchy one paragraph at a time without
understanding the complete exam.

The central requirement is:

        READ THE WHOLE EXAM
               ↓
        UNDERSTAND ITS STRUCTURE
               ↓
        CREATE ONE CANONICAL HIERARCHY
               ↓
        NUMBER THAT HIERARCHY DETERMINISTICALLY

Discovery and numbering are separate operations.

Discovery determines WHAT each block means.

Numbering determines HOW the discovered structure is labeled.

========================================================
D. WHAT DISCOVERY MUST UNDERSTAND
========================================================

The Teacher Exam contains several kinds of material.

Discovery must distinguish at minimum:

- metadata/header
- syllabus/book/chapter information
- section
- major_question
- branch
- passage
- subquestion
- choice
- OR / alternative
- continuation text
- image
- other

The system must understand PARENT/CHILD relationships.

Example:

major question
    passage
    subquestion
        choice
        choice
        choice
        choice
    subquestion
        choice
        choice
        choice
        choice

Another example:

major question
    branch A
        passage
        subquestions
    branch B
        passage
        subquestions

Another example:

major question
    first alternative
    OR
    second alternative

Some question text continues onto another paragraph.

A number may mean a major question in one location and a subquestion

Therefore:

TEXT PREFIX ALONE MUST NOT DETERMINE HIERARCHY.

Context and the complete exam structure matter.

========================================================
M. CANONICAL INTERNAL MODEL
========================================================

Create a simple explicit internal representation.

Keep it easy to inspect.

For example, each block may contain fields such as:

source_id
source_order
original_text
block_type
parent_id
confidence
reason
final_label

Use the simplest suitable Python representation.

A dataclass or Pydantic model is fine.

Do NOT over-engineer.

The canonical structure must exist BEFORE numbering.

========================================================
N. DISCOVERY
========================================================

Discovery should consider the entire document.

If an LLM is used, give it the complete extracted exam structure/text
within practical model limits and ask it to return STRICT structured
data.

The LLM may DISCOVER structure.

The LLM must NOT rewrite academic content.

The returned structure must reference stable source IDs.

Example source IDs:

p0001
p0002
p0003

and image IDs where necessary.

Never accept newly invented question text from the model.

The model returns classifications and relationships, not replacement
content.

========================================================
O. DETERMINISTIC NUMBERING
========================================================

After discovery is complete and validated, run a separate deterministic
numbering step.

Do NOT ask the LLM to write final labels.

The numbering engine should walk the canonical hierarchy.

Desired convention:

Major questions:

Q1)
Q2)
Q3)

Subquestions:

i)
ii)
iii)
iv)

Choices:

a)
b)
c)
d)

Branches where appropriate:

A)
B)

The precise display style can be adjusted later.

For Phase 1, CONSISTENCY and correct hierarchy matter more than typography.

========================================================
P. DO NOT ALTER CONTENT
========================================================

The system may normalize STRUCTURAL LABELS only.

It must not:

- rewrite questions
- fix grammar
- fix spelling
- improve English
- change marks
- replace passages
- generate questions
- remove questions
- reorder questions
- change answer choices
- substitute reference-exam content

Teacher academic content must remain unchanged.

========================================================
Q. IMAGES
========================================================

The Teacher Exam contains an embedded image associated with Q6.

Phase 1 does NOT need to format or resize the image.

But extraction/discovery must preserve its existence and approximate
location/order so it is not silently lost.

Represent it with a stable block/image ID.

No image generation.

No image replacement.

========================================================
R. DIAGNOSTIC OUTPUT
========================================================

Phase 1 output should be intentionally ugly and useful.

Generate a human-readable report such as:

SOURCE | TYPE | PARENT | FINAL LABEL | TEXT

Example:

p0021 | section        | -     | -    | Section A
p0022 | major_question | -     | Q1)  | Read the following...
p0023 | passage        | p0022 | -    | Emperor Ashoka...
p0025 | subquestion    | p0022 | i)   | The Moghuls...
p0026 | choice         | p0025 | a)   | Kashmir...

Also save the canonical hierarchy as JSON.

Suggested outputs:

output/hierarchy.json
output/hierarchy.txt
output/integrity.txt

NO formatted exam DOCX is required in Phase 1.

========================================================
S. VALIDATION
========================================================

Before declaring PASS, validate the canonical hierarchy.

Check at minimum:

1. Every numbered child has a valid parent.
2. Every choice belongs to a valid question/subquestion.
3. Every branch belongs to a major question.
4. OR alternatives belong to a major question.
5. Major questions are in document order.
6. No pre-exam chapter information became a major question.
7. No source block disappeared.
8. No source block was duplicated.
9. Academic text remains unchanged.
10. Images remain represented.
11. Numbering is deterministic.
12. Running numbering twice produces the same result.

========================================================

Create a simple integrity comparison between extracted source content
and canonical output.

Marks integrity

Numerical-value integrity

The canonical representation may change labels but must not change
